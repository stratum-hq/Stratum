This is the simplest path to a multi-tenant API. Express handles HTTP, `pg` handles queries, and PostgreSQL Row-Level Security enforces tenant isolation at the database level. No ORM required.

## What You Get

- Tenant resolution from the `tenant_id` claim of a verified JWT
- Every SQL query automatically scoped to the current tenant
- No manual `WHERE tenant_id = ?` clauses
- Config and permissions resolved per-tenant from the Stratum control plane

### 3. Create Tables with RLS

```sql
-- init.sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "ltree";

-- Application table
CREATE TABLE orders (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  tenant_id UUID NOT NULL,
  product TEXT NOT NULL,
  quantity INTEGER NOT NULL DEFAULT 1,
  total NUMERIC(10,2) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Enable RLS
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
ALTER TABLE orders FORCE ROW LEVEL SECURITY;

-- Tenant isolation policy
CREATE POLICY tenant_isolation ON orders
  USING (tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid);

-- Performance index
CREATE INDEX idx_orders_tenant ON orders (tenant_id, created_at DESC);

-- The application's login. POSTGRES_USER (stratum) is a superuser, and a
-- superuser or a BYPASSRLS role skips every row-level security policy,
-- FORCE included. The app connects as stratum_app, which has neither.
CREATE ROLE stratum_app LOGIN PASSWORD 'stratum_app_dev' NOSUPERUSER NOBYPASSRLS;
GRANT CONNECT ON DATABASE stratum TO stratum_app;
GRANT USAGE, CREATE ON SCHEMA public TO stratum_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON orders TO stratum_app;
```

<Aside type="caution">
  Always include `FORCE ROW LEVEL SECURITY`. Without it, the table owner bypasses
  RLS policies. Stratum's `enableRLS()` helper sets this automatically.
</Aside>

<Aside type="caution" title="Connect as a role that RLS applies to">
  The Docker `POSTGRES_USER` is a superuser. A superuser, or any role with
  `BYPASSRLS`, skips every row-level security policy, so an app that connects as
  `stratum` sees every tenant's rows. Keep that login for bootstrap and
  migrations, and connect the app as `stratum_app`. For production, give
  Stratum its own admin login that is not a superuser either, and limit the
  application login as described in
  [Hardening: separate admin and app roles](/guides/hardening-roles/).
</Aside>

## The Application

### Tenant Middleware

The middleware reads the tenant ID from the `tenant_id` claim of a verified JWT. Then it creates a tenant-scoped connection pool for the request:

```typescript
// src/middleware.ts
import { Pool } from "pg";
import jwt from "jsonwebtoken";
import { createTenantPool } from "@stratum-hq/db-adapters";
import { Request, Response, NextFunction } from "express";

export function tenantMiddleware(pool: Pool, jwtSecret: string) {
  return (req: Request, res: Response, next: NextFunction) => {
    const authorization = req.headers.authorization;
    if (!authorization?.startsWith("Bearer ")) {
      res.status(401).json({ error: "Missing bearer token" });
      return;
    }

    // A token that does not verify is rejected, never ignored.
    let claims: string | jwt.JwtPayload;
    try {
      claims = jwt.verify(authorization.slice("Bearer ".length), jwtSecret, {
        algorithms: ["HS256"],
      });
    } catch {
      res.status(401).json({ error: "Invalid bearer token" });
      return;
    }

    const tenantId = typeof claims === "object" ? claims.tenant_id : undefined;
    if (typeof tenantId !== "string") {
      res.status(401).json({ error: "Token has no tenant_id claim" });
      return;
    }

    // Create a tenant-scoped pool for this request
    req.tenantPool = createTenantPool(pool, () => tenantId);
    req.tenantId = tenantId;
    next();
  };
}
```

<Aside type="caution">
  Do not read the tenant from a request header such as `x-tenant-id`. Any client
  can send that header and select another tenant. Read a header only when a
  gateway you control sets it and removes any copy that the client sent. The SDK
  middleware applies the same rule: with `jwtSecret` set, it reads the header
  only with `trustTenantHeader: true`.
</Aside>

`createTenantPool` returns a pool wrapper that automatically calls `set_config('app.current_tenant_id', tenantId, true)` inside a transaction before every query. RLS policies do the rest.

### Express App

```typescript
// src/index.ts
import express from "express";
import { Pool } from "pg";
import { Stratum } from "@stratum-hq/lib";
import { tenantMiddleware } from "./middleware.js";

const app = express();
app.use(express.json());

// The application login: row-level security applies to it.
const pool = new Pool({
  connectionString: process.env.DATABASE_URL
    || "postgres://stratum_app:stratum_app_dev@localhost:5432/stratum",
});

// Stratum's own login, which runs its migrations. The local superuser is fine
// for development; see the hardening guide for production.
const adminPool = new Pool({
  connectionString: process.env.DATABASE_ADMIN_URL
    || "postgres://stratum:stratum_dev@localhost:5432/stratum",
});

const stratum = new Stratum({ adminPool, pool, autoMigrate: true });

// The tenant binding comes from a signed token, so the server does not start
// without the key that verifies it.
const jwtSecret = process.env.JWT_SECRET;
if (!jwtSecret) {
  throw new Error("JWT_SECRET is required to verify bearer tokens.");
}

// Apply tenant middleware to all /api routes
app.use("/api", tenantMiddleware(pool, jwtSecret));

// List orders (automatically filtered by RLS)
app.get("/api/orders", async (req, res) => {
  const result = await req.tenantPool.query(
    "SELECT * FROM orders ORDER BY created_at DESC"
  );
  res.json(result.rows);
});

// Create an order
app.post("/api/orders", async (req, res) => {
  const { product, quantity, total } = req.body;
  const result = await req.tenantPool.query(
    "INSERT INTO orders (tenant_id, product, quantity, total) VALUES ($1, $2, $3, $4) RETURNING *",
    [req.tenantId, product, quantity, total]
  );
  res.status(201).json(result.rows[0]);
});

// Get order by ID (RLS ensures it belongs to the current tenant)
app.get("/api/orders/:id", async (req, res) => {
  const result = await req.tenantPool.query(
    "SELECT * FROM orders WHERE id = $1",
    [req.params.id]
  );
  if (result.rows.length === 0) {
    res.status(404).json({ error: "Order not found" });
    return;
  }
  res.json(result.rows[0]);
});

// Delete an order (RLS prevents deleting another tenant's order)
app.delete("/api/orders/:id", async (req, res) => {
  const result = await req.tenantPool.query(
    "DELETE FROM orders WHERE id = $1 RETURNING *",
    [req.params.id]
  );
  if (result.rows.length === 0) {
    res.status(404).json({ error: "Order not found" });
    return;
  }
  res.json({ deleted: result.rows[0] });
});

// Health check (no tenant required)
app.get("/health", (req, res) => {
  res.json({ status: "ok" });
});

async function main() {
  await stratum.initialize();
  app.listen(3000, () => console.log("Listening on :3000"));
}

main();
```

## Testing Isolation

Create two tenants and verify they cannot see each other's data. Your identity provider issues the tokens in a real application. For local tests, sign one token for each tenant with the same `JWT_SECRET` as the server:

```bash
# Create tenants via Stratum control plane
TENANT_A="aaaaaaaa-0000-0000-0000-000000000001"
TENANT_B="bbbbbbbb-0000-0000-0000-000000000002"

# Sign a token for each tenant
TOKEN_A=$(node -e 'console.log(require("jsonwebtoken").sign({ tenant_id: process.argv[1] }, process.env.JWT_SECRET, { algorithm: "HS256", expiresIn: "1h" }))' "$TENANT_A")
TOKEN_B=$(node -e 'console.log(require("jsonwebtoken").sign({ tenant_id: process.argv[1] }, process.env.JWT_SECRET, { algorithm: "HS256", expiresIn: "1h" }))' "$TENANT_B")

# Insert orders for Tenant A
curl http://localhost:3000/api/orders -X POST \
  -H "Authorization: Bearer $TOKEN_A" \
  -H "Content-Type: application/json" \
  -d '{"product": "Widget", "quantity": 5, "total": "49.95"}'

curl http://localhost:3000/api/orders -X POST \
  -H "Authorization: Bearer $TOKEN_A" \
  -H "Content-Type: application/json" \
  -d '{"product": "Sprocket", "quantity": 10, "total": "99.90"}'

# Insert orders for Tenant B
curl http://localhost:3000/api/orders -X POST \
  -H "Authorization: Bearer $TOKEN_B" \
  -H "Content-Type: application/json" \
  -d '{"product": "Gadget", "quantity": 2, "total": "29.90"}'

# Tenant A sees 2 orders (Widget + Sprocket)
curl http://localhost:3000/api/orders -H "Authorization: Bearer $TOKEN_A"

# Tenant B sees 1 order (Gadget)
curl http://localhost:3000/api/orders -H "Authorization: Bearer $TOKEN_B"

# Tenant B cannot delete Tenant A's order (returns 404, not 403)
ORDER_A_ID=$(curl -s http://localhost:3000/api/orders \
  -H "Authorization: Bearer $TOKEN_A" | jq -r '.[0].id')

curl -X DELETE "http://localhost:3000/api/orders/$ORDER_A_ID" \
  -H "Authorization: Bearer $TOKEN_B"
# {"error": "Order not found"}
```

The last test is the important one. Tenant B tries to delete Tenant A's order by ID. RLS filters the DELETE query, so no row matches, and the API returns 404. The tenant never knows the order exists.

## Adding More Tables

Use Stratum's migration helpers to add RLS to new tables:

```typescript
import { migrateTable } from "@stratum-hq/db-adapters";

const client = await pool.connect();
try {
  await client.query("BEGIN");
  await migrateTable(client, "invoices");
  await migrateTable(client, "products");
  await client.query("COMMIT");
} finally {
  client.release();
}
```

Or use the CLI:

```bash
npx @stratum-hq/cli migrate invoices products
```
