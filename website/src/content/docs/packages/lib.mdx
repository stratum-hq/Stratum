`@stratum-hq/lib` is the direct library for embedding Stratum in your Node.js application. It talks directly to PostgreSQL with no HTTP server in between, giving you maximum performance for tenant operations.

## Installation

```bash
npm install @stratum-hq/lib @stratum-hq/core pg
```

## When to Use

| Use Case | Package |
|----------|---------|
| Node.js app, maximum performance | `@stratum-hq/lib` |
| Serverless functions | `@stratum-hq/lib` |
| Testing and scripting | `@stratum-hq/lib` |
| Polyglot stack, service separation | `@stratum-hq/sdk` + control plane |
| React admin UI | `@stratum-hq/sdk` + `@stratum-hq/react` |

## Quick Start

```typescript
import { Pool } from "pg";
import { Stratum } from "@stratum-hq/lib";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const stratum = new Stratum({ pool });

const tenant = await stratum.createTenant({
  name: "Acme Corp",
  slug: "acme_corp",
  isolation_strategy: "SHARED_RLS",
});

const config = await stratum.resolveConfig(tenant.id);
const permissions = await stratum.resolvePermissions(tenant.id);
```

## Constructor

```typescript
const stratum = new Stratum({
  pool: pgPool,              // Required: pg.Pool instance
  keyPrefix: "sk_live_",     // Optional: API key prefix (default: "sk_live_")
  logger: myLogger,          // Optional: StratumLogger (default: defaultLogger)
  autoMigrate: false,        // Optional: run migrations on initialize() (default: false)
  enforceRls: false,         // Optional: hard-fail initialize() and migrations if the PG role has BYPASSRLS (default: false)
});
```

The pool is **borrowed, not owned**: Stratum never creates or closes the pool. You manage the pool lifecycle.

```typescript
stratum.initialize(): Promise<void>
```

Call `initialize()` once before using any other method. When `autoMigrate` is enabled it runs migrations (with an advisory lock so concurrent calls are safe); with `autoMigrate: false` it is a cheap no-op that still marks the instance ready. It is safe to call concurrently; every caller awaits the same promise. Set `enforceRls: true` in every deployment other than development and test so `initialize()` and migrations refuse to run under a `BYPASSRLS` role. The role is checked on every `initialize()`, with or without `autoMigrate`, and on every `migrate()` call, not only when a migration is applied. `initialize()` logs a warning when `autoMigrate` is on and `enforceRls` is off there.

## API Reference

### Tenants

```typescript
stratum.createTenant(input, audit?): Promise<TenantNode>
stratum.getTenant(id, includeArchived?): Promise<TenantNode>
stratum.getTenantBySlug(slug, includeArchived?): Promise<TenantNode>
stratum.listTenants(pagination): Promise<PaginatedResult<TenantNode>>
stratum.updateTenant(id, patch, audit?): Promise<TenantNode>
stratum.deleteTenant(id, audit?): Promise<void>
stratum.moveTenant(id, newParentId, audit?): Promise<TenantNode>
stratum.getAncestors(id): Promise<TenantNode[]>
stratum.getRoot(id): Promise<TenantNode>
stratum.getDescendants(id, includeArchived?): Promise<TenantNode[]>
stratum.getChildren(id): Promise<TenantNode[]>
stratum.reorderTenant(id, position, audit?): Promise<TenantNode>
stratum.batchCreateTenants(inputs, audit?): Promise<BatchCreateResult>
stratum.getTenantContext(tenantId, options?): Promise<TenantContext>
```

- `getTenantBySlug(slug, includeArchived?)`: resolve a tenant by its globally unique slug in one indexed lookup, the slug-keyed counterpart to `getTenant`. Throws `TenantNotFoundError` when no row matches, and (unless `includeArchived` is set) `TenantArchivedError` / `TenantSuspendedError` for a non-active row.
- `getRoot(id)`: the root ancestor of any tenant (the tenant itself when it is already a root), resolved with single-row lookups rather than by walking the full ancestry chain.
- `getDescendants(id, includeArchived?)`: the descendant subtree, shallowest first. Excludes archived and soft-deleted tenants by default; pass `includeArchived` for the full historical subtree.
- `batchCreateTenants(inputs, audit?)`: creates every tenant in a single transaction (all-or-nothing). On any failure nothing persists and the result is `{ created: [], errors: [<first failure>] }`; wrap per-tenant `createTenant` calls yourself if you need partial success.

### Tenant lifecycle

Tenants move through an explicit state machine: active to suspended or archived, and either back to active or on to a purge.

```typescript
stratum.suspendTenant(id, audit?): Promise<TenantNode>
stratum.resumeTenant(id, audit?): Promise<TenantNode>
stratum.archiveTenant(id, audit?): Promise<TenantNode>
```

- `suspendTenant`: a reversible block on access. Rejects if the tenant is not active or has active children (suspend leaf-first). Reverse with `resumeTenant`.
- `archiveTenant`: a reversible soft delete. Accepts an active or suspended tenant; rejects if already archived or it has active children. Reverse with `resumeTenant`. This is the canonical name for what `deleteTenant` does.
- `resumeTenant`: returns a suspended or archived tenant to active. Rejects if the tenant is already active or its parent is not active (resume top-down).
- `deleteTenant(id, audit?)` is retained as a **deprecated alias of `archiveTenant`**; prefer `archiveTenant`.

See the [tenant lifecycle guide](/guides/tenant-lifecycle/) for the full state machine and descendant rules.

### Config

```typescript
stratum.resolveConfig(tenantId, options?): Promise<ResolvedConfig>
stratum.setConfig(tenantId, key, input, audit?): Promise<ConfigEntry>
stratum.deleteConfig(tenantId, key, audit?): Promise<void>
stratum.getConfigWithInheritance(tenantId, options?): Promise<ResolvedConfig>
stratum.batchSetConfig(tenantId, entries, audit?): Promise<BatchSetConfigResult>
stratum.diffConfig(tenantIdA, tenantIdB, options?): Promise<ConfigDiff>
stratum.computeDrift(parentId, childId): Promise<DriftResult>
stratum.batchComputeDrift(parentId, childIds): Promise<BatchDriftResult>
```

- `resolveConfig(tenantId, options?)`: a sensitive value inherited from an ancestor comes back masked: `value: null`, `sensitive: true`, `masked: true`, with `source_tenant_id` naming the tenant that set it. A tenant's own sensitive values come back decrypted. Pass `{ revealSensitive: true }` in trusted server code that needs the inherited secret itself, and never send that result to a client. Pass `{ viewerTenantId }` to reveal only the values that tenant set. `getConfigWithInheritance`, `getTenantContext` and `diffConfig` take the same options.
- `batchSetConfig(tenantId, entries, audit?)`: atomic. If any key is locked by an ancestor or invalid, nothing is written and the result has `rolled_back: true` and `succeeded: 0`. Every result then has status `error`: the keys that caused the rollback carry their own reason, and the rest say they were not applied.
- `computeDrift(parentId, childId)`: classify each resolved config key on the child against the parent as `ok` / `override` / `missing` / `conflict` (a `conflict` is a child value that diverges from a **locked** parent key), with per-key detail and a rolled-up worst status.
- `batchComputeDrift(parentId, childIds)`: `computeDrift` fanned out over many children, with a per-status summary count.

### API Keys

```typescript
stratum.createApiKey(tenantId, nameOrOptions?, expiresAt?): Promise<CreatedApiKey>
stratum.validateApiKey(key): Promise<ValidatedApiKey | null>
stratum.revokeApiKey(keyId): Promise<boolean>
stratum.rotateApiKey(keyId, newName?): Promise<CreatedApiKey>
stratum.listApiKeys(tenantId?): Promise<ApiKeyRecord[]>

```

- `createApiKey(tenantId, ...)`: `tenantId` is `null` for a global key, which is not limited to one tenant.
- `validateApiKey(key)`: on success, sets the key's `last_used_at` before the promise resolves, so `listDormantKeys` called next does not report the key. It skips that update when `last_used_at` is less than 60 seconds old, so `last_used_at` can lag the latest use by up to one minute. The update waits at most one second. A failure or timeout of that update does not fail the validation.
- `getApiKey(id)`: look up a single API key by id, including its owning tenant; returns `null` when no key has that id. The primitive for authorizing an operation that targets a key by id whose owning tenant is not otherwise in the request.

### Audit Logs

```typescript

stratum.getAuditEntry(id): Promise<AuditEntry | null>
stratum.recordAuditEvent(input): Promise<AuditEntry>
```

- `recordAuditEvent(input)`: append a custom event to Stratum's `audit_logs` through the public surface (Stratum owns the table and otherwise exposes only reads). The input is validated and written on the same path the internal services use, so the entry is indistinguishable from one Stratum writes itself and is immediately queryable via `queryAuditLogs`. The row is stamped for `input.tenantId` and no other tenant. Pass an optional `occurredAt` (ISO 8601 string or `Date`) to set the row's `created_at` when seeding historical or backdated events; omit it and the row is stamped `now()`.   resourceId,

```typescript
  after,
```

- `resolvePrincipalScopes(principalType, principalId, tenantId?)`: the principal's effective scopes via its assigned role, or `[]` when unassigned (fails closed). With `tenantId`, a role owned by another tenant is ignored while global roles still resolve.

### Encryption

Stratum encrypts config values set with `sensitive: true` and webhook secrets with AES-256-GCM. The key comes from `STRATUM_ENCRYPTION_KEY`, with `STRATUM_HKDF_SALT` as the key-derivation salt. Both are required whenever `NODE_ENV` is not `development` or `test` (an unset `NODE_ENV` counts as `development`); only development and test fall back to a built-in key. Outside development and test the library refuses to load unless `STRATUM_ENCRYPTION_KEY` is at least 32 bytes and is not the built-in development key, and `STRATUM_HKDF_SALT` is not the built-in development salt. In every environment, a `STRATUM_HKDF_SALT` that is set must be a non-empty, even-length hex string. The legacy `WEBHOOK_ENCRYPTION_KEY` variable is read only in development and test; elsewhere, set `STRATUM_ENCRYPTION_KEY` to its value. The package does not export the encryption functions; use the `Stratum` method below to change the key.

```typescript
stratum.rotateEncryptionKey(oldKey, newKey, audit?, salts?): Promise<KeyRotationResult>

interface KeyRotationSalts {
  oldSalt?: string;  // hex; the salt the existing values use. Default: STRATUM_HKDF_SALT
  newSalt?: string;  // hex; the salt the run encrypts under. Default: STRATUM_HKDF_SALT
}
```

`rotateEncryptionKey` re-encrypts sensitive config values and webhook secrets in batches of 100. It decrypts each value with the old key and the old salt, and encrypts it with the new key and the new salt. Each batch commits in its own transaction. If a run fails partway, run it again with the same keys and salts. The second run skips values that already decrypt with the new key and the new salt.

To change only the salt, give the same key as `oldKey` and `newKey`.

During a rotation, `STRATUM_ENCRYPTION_KEY_PREVIOUS` and `STRATUM_HKDF_SALT_PREVIOUS` keep values that are not yet rotated readable. If the current key and salt do not decrypt a value, Stratum tries the previous key with the previous salt. If only one of the two previous variables is set, the other one uses its current value.

### Moving off the built-in development key

In `development` and `test` (and when `NODE_ENV` is unset), Stratum falls back to a built-in development key and a built-in HKDF salt when `STRATUM_ENCRYPTION_KEY` and `STRATUM_HKDF_SALT` are not set. Every other environment refuses to start without both. Values encrypted under the fallback must be re-encrypted before the deployment runs with real key material. Move them to a new random key and a new random salt in this order:

1. Set `STRATUM_ENCRYPTION_KEY` to new random key material.
2. Set `STRATUM_HKDF_SALT` to a new random salt in hex, for example the output of `openssl rand -hex 32`. An HKDF salt is not secret.
3. Set `STRATUM_ENCRYPTION_KEY_PREVIOUS` to `stratum-dev-key`.
4. Set `STRATUM_HKDF_SALT_PREVIOUS` to the hex form of the built-in salt, `7374726174756d2d6e6f6e2d70726f64756374696f6e2d686b64662d73616c742d7631`. Steps 3 and 4 keep existing values readable until the rotation finishes.
5. Restart the deployment, so that it reads the new variables.
6. Rotate from the built-in pair to the new pair. If the run fails partway, run it again with the same arguments:

```typescript
await stratum.rotateEncryptionKey("stratum-dev-key", process.env.STRATUM_ENCRYPTION_KEY!, undefined, {
  oldSalt: process.env.STRATUM_HKDF_SALT_PREVIOUS,
  newSalt: process.env.STRATUM_HKDF_SALT,
});
```

7. Examine anything the result lists in `unreadable`.
8. Unset `STRATUM_ENCRYPTION_KEY_PREVIOUS` and `STRATUM_HKDF_SALT_PREVIOUS`.

Keep the new salt afterwards. Data encrypted under a salt that is not configured cannot be read. To change the salt again later, rotate with that salt as `oldSalt`.

To rotate through the control plane, do steps 1 to 5 for the control plane deployment. For step 6, call `POST /api/v1/maintenance/rotate-encryption-key` with the built-in pair as the old pair and the new pair as the new pair:

```json
{
  "old_key": "stratum-dev-key",
  "new_key": "<the value of STRATUM_ENCRYPTION_KEY>",
  "old_salt": "7374726174756d2d6e6f6e2d70726f64756374696f6e2d686b64662d73616c742d7631",
  "new_salt": "<the value of STRATUM_HKDF_SALT>"
}
```

The route accepts the same key as `old_key` and `new_key` when `old_salt` and `new_salt` differ. A salt that the body does not give is the configured `STRATUM_HKDF_SALT`.

A salt must be a non-empty, even-length hex string. `rotateEncryptionKey` throws a `ValidationError` for any other salt and changes no row. The control plane route answers `400 VALIDATION_ERROR`.

```typescript
interface KeyRotationResult {
  config_entries_rotated: number;  // values re-encrypted by this run
  webhooks_rotated: number;
  already_rotated: number;         // values that already decrypt with the new key and salt
  unreadable: KeyRotationUnreadableRow[];  // values that decrypt with neither pair
}

interface KeyRotationUnreadableRow {
  table: "config_entries" | "webhooks";
  id: string;
}
```

A value in `unreadable` stays unchanged, and the run continues. Examine each one before you remove the old key. When some values are unreadable, the run logs the warning `encryption key rotation left unreadable rows`.

If encrypted values exist and none of them decrypts with the old key or the new key, `rotateEncryptionKey` throws a `ValidationError` and changes no row. This result almost always means that the old key or the old salt is wrong.

### Usage metering

```typescript
stratum.recordUsage(tenantId, input): Promise<UsageEvent>
```

### Tenant context (AsyncLocalStorage)

Static helpers that read and run within the request-scoped tenant context. They wrap the same `AsyncLocalStorage` the SDK and adapters use, so `Stratum.currentTenantId()` sees a tenant set by any middleware in the chain.

```typescript
Stratum.currentTenantId(): string | undefined
Stratum.currentTenantContext(): ResolvedTenantContext | undefined
Stratum.runWithTenant<T>(ctx, fn): T
```

`currentTenantId` / `currentTenantContext` return `undefined` when called outside an active context. `runWithTenant(ctx, fn)` executes `fn` with `ctx` as the active context.

## Top-level exports

Beyond the `Stratum` class, `@stratum-hq/lib` exports helpers you can use directly:

```typescript
import {
  migrate,             // migrate({ pool, enforceRls? }): run the Stratum migrations
  migrateAllSchemas,   // migrateAllSchemas(...): multi-schema migration runner
  STRATUM_TABLES,      // readonly string[]: the tables the Stratum migrations create
  runScopedJob,        // runScopedJob(pool, tenantId, fn): tenant-scoped background job
  verifyWebhookSignature,
  signWebhookPayload,
  DEFAULT_WEBHOOK_TOLERANCE_SECONDS,
  RateLimiter,         // standalone per-tenant fixed-window limiter
  MemoryRateLimitStore,
} from "@stratum-hq/lib";
```

- `runScopedJob(pool, tenantId, fn)` runs `fn` bound to a single tenant, establishing both the AsyncLocalStorage tenant context and the Postgres RLS context (`SET LOCAL app.current_tenant_id`) for the job's duration and tearing both down afterward, so a job cannot touch another tenant's rows and the context never leaks onto the next job on a pooled connection.
- `STRATUM_TABLES` lists the `public` tables that the Stratum migrations create, plus `_migrations`. Use it to tell Stratum's tables from your application tables. The CLI's `scan` and `migrate --all` skip these tables.
- `verifyWebhookSignature({ secret, payload, signature, timestamp })` validates an incoming delivery's HMAC signature and timestamp freshness (default window `DEFAULT_WEBHOOK_TOLERANCE_SECONDS`). See the [webhooks guide](/guides/webhooks/).

## Prerequisites

`@stratum-hq/lib` assumes the Stratum database schema exists. Run the control plane migrations first, or apply the migration SQL manually:

```bash
# Option 1: Start the control plane (runs migrations automatically)
node packages/control-plane/dist/index.js

# Option 2: Apply SQL directly
psql -d stratum -f packages/control-plane/src/db/migrations/001_init.sql
```

## Error Handling

All errors come from `@stratum-hq/core`:

```typescript
import {
  TenantNotFoundError,
  TenantArchivedError,
  ConfigLockedError,
  PermissionLockedError,
  PermissionRevocationDeniedError,
} from "@stratum-hq/core";

try {
  await stratum.setConfig(childId, "locked_key", { value: 500 });
} catch (err) {
  if (err instanceof ConfigLockedError) {
    console.log("Cannot override locked key");
  }
}
```
